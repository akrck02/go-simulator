📖 Vocabulary and conditions

Plugins never talk to each other, so they need to agree on names. If the terrain calls the height of the ground elevation and the climate looks for elevation, they work together without knowing the other exists. This page lists those shared names, their units, and the little language used everywhere to say “when does this apply”.

Units

Positions and the sizes of shapes are in world units, the unit of the scene, on the ground plane (x east, z south) with y up: they are what gets drawn. Fields and properties are data, in the physical units written next to their names, so models read them without knowing the scale of the scene. Plugins that need metres from world units take a metres_per_unit parameter (1000 for scenes in kilometres).

Shared names

Defined in world/vocabulary.go. Names outside the vocabulary are allowed, but a name another plugin may want to read belongs here.

Kinds

street (a line with a width; class says which), parcel (a plot), building (a volume), wall, gate, square, bridge, river, tree (its species), anchor.

Properties

year (when it appeared, in the stage’s clock), use (housing, shop, workshop…), floors, class, sector, species, anchor (true on anchors), role (what an anchor means).

Overlay properties

Any entity can carry a few words for whoever watches the run. The live viewer (labels, header and notices) draws them over the 3D scene; models should not read them. All are optional, and setting one to null takes it away.

Name Value Shown as
label text a short text in a light pill above the entity
icon text: a Lucide icon name an icon before the label, or alone in a circle
badge text (or a number) a very short text in a small pill under the label: 7/10
label_color "#rrggbb" the colour of the icon and the badge; the text stays dark so it always reads well
pinned a number the label goes to the header, top-left, as that line (1 first) instead of above the entity; such entities need no shape 
{"op": "add", "entity": {"id": "ferry", "kind": "boat", "shape": {"primitive": "box", "size": [4, 2, 10]},
  "properties": {"label": "Ferry → quay", "icon": "ship", "badge": "12/40", "label_color": "#2563eb"}}}
{"op": "add", "entity": {"id": "harbour-clock", "properties": {"label": "08:25", "icon": "clock", "pinned": 1}}}

Events

Name Data
biomes names: the values of the biome field
vegetation names, labels, forms, heights: the values of the vegetation field

Events that name the categories of a field carry {"names": […]}.

Any event can also carry a notice, a short message for whoever watches: notice (the text) and, optionally, icon (a Lucide icon name) and label_color. The live viewer shows it under its header for a few seconds, newest first, then fades it out:

{"op": "emit", "event": {"name": "arrivals", "data": {"notice": "Boat 4 moored at the north quay", "icon": "anchor"}}}

Conditions

“Buildings with three or more floors”, “cells colder than 7 °C”, “shops or workshops”: many parts of the system need to say when something applies, and they all use the same small language, in objectives, habitats, biome rules, managed land and scene styles (package conditions). A condition is a map from a fact to what it must be; every entry must hold.

Written Holds when the fact is
kind: building equal to the value (numbers by value, the rest by text)
use: [shop, workshop] one of the values
floors: {min: 2, max: 3} a number in the range (either end may be left out)
river: true that yes/no value

A fact that does not exist never holds. For entities, the facts are kind and their properties; for cells of a grid, the plugin says which facts it offers (the flora: temperature, precipitation, elevation, slope, biome and distance_to_<anchor>). Rules files are checked before a run: ranges take only min and max, and their bounds must be numbers.
